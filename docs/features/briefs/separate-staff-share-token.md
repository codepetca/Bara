# Staff sign-in for attendance access

- Goal: scanning the student QR must never grant roster access or authority to mark another student.
- Decision: staff sign in through the existing Bara WorkOS application. Every roster read and manual attendance operation verifies an active app user, an active staff/admin membership in the roster organization, and explicit roster access. Shared manual URLs identify the session; possession is not authorization.
- Student flow: scan the existing per-session QR, sign in, and check in only as the matched student. No QR reassignment/location behavior is included in this security release.
- Projector: public `/s/display/<checkInToken>` receives only safe session context and aggregate counts. The authenticated display uses counts-only queries too. Neither projector query returns participant rows, identity fields, or audit events. Erasure and roster-decommission fences apply.
- Staff flow: copy/open the existing manual URL, complete sign-in if needed, then mark attendance for an authorized roster. The authenticated staff actor is recorded in the audit. Closed shared editors are unavailable; staff retain ID-based history and closed writes remain blocked.
- Data compatibility: no staff bearer credentials are generated or backfilled. Preserve optional legacy `staffShareToken` fields/indexes without consulting them for access. No stored records are deleted or migrated. Existing student links keep working.
- Rollout: replace draft PR66 with the staff-authenticated implementation, preserving its production guards. Run backend/UI/route tests, required local checks, independent security/compatibility reviews, and the hosted WorkOS callback plus Convex authenticated app-state gate before cutover. Backend authorization lands before matching frontend; no staff-token migration/preflight is required. Follow production with the same security change on main to prevent reintroducing bearer access.
- Acceptance: anonymous, student, unrelated staff, stale/disabled membership/user/organization, and cross-roster callers cannot read roster data or mark attendance. Authorized roster staff/admin can read and mark open sessions; authenticated actors are audited. Projector payloads contain only counts/context and maintain erasure/decommission and closed-state behavior.
