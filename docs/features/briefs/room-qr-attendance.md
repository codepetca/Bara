# Room QR attendance

## User goal

Set up one display per classroom so students can check in to every class they attend there with one scan. Show a fresh room QR for each new class meeting and each day. Give teachers a quick way to move a class when the room changes.

## UX flow

- **Room display.** Pair the monitor once. While any class is accepting check-ins, show the room number, **Scan to check in**, and one large QR in a fixed position. The code stays the same while the same check-in windows are open. Between check-in windows, keep one QR in the same spot with **Check-in closed** and a teacher move prompt. Notices can cycle beside the code with a pause control. If the monitor loses its connection and cannot verify the current code, show **Check in with your teacher** and resume automatically on reconnect.
- **Student.** Scan, sign in if needed, and automatically check in to every class accepting scans in that room whose roster matches the student. At 10 a.m. in Room 223, a student enrolled in Class A checks into A, a student enrolled in B checks into B, and a student enrolled in both sees **Checked in for Class A and Class B**. When a check-in needs teacher help, identify the affected class alongside any successful check-ins. With no match, direct the student to their teacher.
- **Teacher.** Start or stop QR check-in for each class independently. Start today’s meeting even if yesterday’s is still open for manual corrections. To relocate, scan the Room 220 display and tap **Move Class A here**. Eligible standalone meetings are today’s open meetings the teacher can manage that are assigned to another room or have no room yet. Offer a choice only if several meetings qualify. With none, offer **Set default room** for an authorized standalone class. A move carries over attendance and offers **Undo** and **Make Room 220 the default**. The default applies to future meetings and is editable in class settings. The same display QR opens room controls even when the destination is empty. A staff sticker remains optional for when the display is off.

## Primary action

Students scan once. For a teacher who scans the destination room with one active class, **Move Class A here** is one tap after sign-in. **Stop QR check-in** ends student self-service, while **Close attendance** finalizes the meeting after manual corrections.

## Architecture plan

- **Room access and scan routing.** Give each room a stable link and pair the monitor with a revocable credential scoped to that room. The on-screen QR carries the room link and a student proof tied to the current check-in windows. Only the paired monitor can fetch current proofs. After WorkOS sign-in, a staff scan opens authorized room controls even if the student proof is no longer valid. Student accounts continue automatically with a valid scan. Accounts eligible for both paths choose **Manage room** or **Check in as student** before any write. The staff sticker opens only the staff path. Keep student names and individual marks in the authenticated editor and preserve `app_users`, `auth_identities`, and `rosters.ownerAppUserId`.
- **QR changes and sign-in.** Bind the proof to the room, the room’s local date, and the current set of meeting check-in windows. Issue a new proof when that set changes, including when a class starts, stops, or moves, and for the first check-in on a new day. Hide the student QR when no windows are open. A replaced proof or a proof from a previous day cannot start a student check-in. A scan accepted before the change gets up to **2 minutes from server entry** to complete check-in through WorkOS in the same browser, within the same local date and subject to each captured window still being open. Consume the continuation once. A retry in the same browser and account can return the recorded result. Reloading cannot extend the deadline.
- **Automatic stop.** End each meeting’s QR check-in at the earliest of **10 minutes after the teacher starts it**, the scheduled meeting end when known, or the end of the meeting’s local day. Enforce the cutoff on the server at both scan entry and submission. Teachers can stop sooner or explicitly start a fresh window for an open meeting on its own date, before its scheduled end when known.
- **Local day boundary.** Use the school’s local time zone for its rooms (`America/Toronto` in the pilot). At local midnight, prior-day meetings drop out of the display and move picker. Enforce the meeting date on the server for opening a check-in window, redeeming a scan, moving a meeting, and undoing a move. Keep prior-day meetings accessible for manual corrections until a teacher closes them. For room-mode rosters, scope the active-meeting lookup and duplicate check to the roster and today’s local date so an open prior-day meeting cannot block starting today’s.
- **Room moves and scan scope.** Track the default room per roster and the current room per meeting. Move the meeting in one transaction and let both displays update. Track a revision for the room assignment and a revision for the check-in window. Each move, including Undo, advances the room revision. Each new or stopped window advances the window revision. Capture the accepting meetings and both revisions at valid scan entry. At submission, require the same revisions and an open window for each captured meeting. Classes added after scan entry need a fresh scan. Undo requires an open meeting and the room revision produced by the move. It restores only that meeting’s prior room, while saving the default is a separate change.
- **Server enforcement.** Room QR is a mode selected per meeting and kept through its close. Reject legacy student session tokens at the server for room-mode meetings, including before check-in starts and after it stops. Apply the restriction at every student check-in entry point. Authorize Pika room changes through Pika’s signed integration and classroom access checks.
- Reuse verified participant matching and attendance rules for each eligible meeting. Record each class outcome, preserve manual marks, and make retries safe. Treat duplicate or ambiguous identity records within one roster as a review case for that class.

## Risks and pilot scope

- A photo of the current code can still be used during the same check-in window. A photo from a previous class or day cannot start a new check-in. Use actual scan and sign-in times to tune the window and sign-in grace period in the pilot.
- Pilot with one paired display per room. Configure rooms for Pika classes from Pika’s Daily attendance surface. Keep announcements simple so the QR stays easy to scan from the back of the room.

## Acceptance criteria

- **QR changes and sign-in.** The same QR remains visible after five minutes when the same windows are open. Opening, closing, or moving a check-in window changes the QR for affected rooms that still have open windows. The QR disappears when the last window closes. The first check-in on the next local day shows a new QR, even for the same roster. Photos of replaced codes and prior-day codes cannot start a check-in. A student who entered in time can finish WorkOS sign-in within two minutes in the same browser on the same local day for any captured class still accepting the scan. A second browser cannot use the continuation. Reloading cannot extend its deadline. Retrying a completed check-in creates no second mark.
- **Automatic stop.** Leave A running and start B in the same room. After A’s ten-minute cutoff or its earlier scheduled end, a student enrolled in both gets a new mark only in B. A sign-in that started before A’s cutoff cannot add an A mark after it. A’s teacher can still mark attendance manually.
- **Monday to Tuesday.** Leave Monday’s meeting open with no scheduled end. After local midnight, a photo of Monday’s QR and a sign-in begun Monday both fail to add a mark. Monday’s meeting disappears from the move picker, and the server rejects attempts to reopen its QR window or move it. On Tuesday, start a new meeting for the same roster while Monday is still open. Tuesday’s fresh QR marks only Tuesday. The teacher can still open Monday’s attendance and save a manual correction while Tuesday is running.
- **Server enforcement.** Direct use of legacy student URLs or APIs fails for a room-mode meeting before, during, and after its QR window. A Pika-linked roster cannot enable room mode through standalone Bara controls. An unpaired or revoked display cannot fetch a live proof.
- **Staff scan.** A signed-in teacher scanning an expired QR or the staff sticker reaches the room controls. One eligible meeting takes one tap to move, several offer a choice, and zero offer only the default-room action when an eligible class exists. An account eligible for both roles must explicitly choose student check-in to write a student mark. An unauthorized account cannot move a meeting or change its default.
- **Moves and Undo.** Move A from Room 223 to Room 220 while B stays in 223. Existing marks carry over and fresh scans work in each room for its assigned classes. A Room 223 scan captured before the move can still mark B if eligible, even if A returns through Undo before submission. A requires a fresh scan, as does any class that opens or restarts check-in during sign-in. A stale Undo cannot overwrite a later move. Saving the new default applies to future meetings, and Undo of the current move leaves that default in effect.
- **Shared-room results.** With A and B both accepting scans in Room 223, students enrolled in A, B, and both get exactly the expected marks. An ambiguous match in one roster leaves it for teacher review and still marks the other eligible roster. Repeated scans preserve teacher corrections.
- Cover these rules in Convex and the sign-in and display flows in Playwright. Verify scanning from the back row and monitor recovery after a disconnect in the classroom pilot.

### Closed-room QR acceptance

- A paired, connected iPad shows exactly one QR in both states. During check-in, the QR carries the current attendance proof. Between windows, it carries the room link without a proof. Keep notices visible in both states and show the existing unavailable state if the display disconnects or loses pairing.
- A teacher can scan the closed Room 220 QR, sign in if needed, and move the open P5 meeting without changing its Room 223 default. Room 220’s display then shows the live check-in QR while P5 accepts attendance.
- A student scanning the closed QR gets **Check-in is closed**. Opening the same saved URL after any attendance window opens never captures or redeems a scan, even with a previous scan cookie in the browser. A fresh live scan still checks in to every matching open class.

## Pilot setup

Use a shared Bara organization for teachers whose classes will use the same room. A deployment operator can authorize a verified WorkOS user ID through the internal Convex function `roomMemberships:authorize` using a standalone roster ID in that organization. Use `role: "student"` with a verified roster student ID or school email. Use `role: "staff"` to let another teacher create their own rosters in the shared organization. Bara applies the grant on the next account bootstrap. Existing rosters keep their organization and staff access. For an active staff member who is also enrolled in a class, the operator can link the verified WorkOS account to that participant with `roomMemberships:linkStaffParticipant` after their first sign-in. Confirm one signed-out student can complete WorkOS sign-in and receive a mark in the intended environment before starting the classroom pilot.

## Pika integration

- In Pika’s Daily attendance menu, open **Attendance rooms**. Create and pair a room once and choose the same default room in each class that meets there. The Bara monitor opens the room QR when an assigned Pika meeting starts accepting attendance. Pika uses its configured attendance window through its configured close time or Toronto midnight, whichever comes first. Pika rooms are shared by entitled classes in the same integration tenant. Pair a room before assigning it. Classes that start with an unpaired default use the existing classroom QR. Standalone Bara rooms have separate setup.
- The monitor’s QR sends students to Pika. Bara captures which Pika meetings are accepting the scan. Pika checks signed-in identity, classroom access and active enrollment for each candidate, then submits one existing signed attendance command per match. Bara records the facts and sends the existing attendance events to Pika. Pika uses the established enrollment resolver for each learner and requires an active participant generation for room scans. Each class keeps its own present/late cutoff and teacher corrections.
- Scan a destination display or staff sticker to move an open class. Moving keeps the existing attendance and stops that class accepting scans in its previous room. Optionally save the new default for future meetings. Undo restores the current meeting’s prior room and leaves a separately saved default in place. Undo for a meeting that started without a room restores the usual Pika classroom QR with a fresh session token.
- Release requires the existing Pika attendance entitlement and enrollment-generation support plus the public Bara display origin in Pika’s configuration (`BARA_ATTENDANCE_ROOM_DISPLAY_ORIGIN`). Deploy the Bara backend and display before enabling room controls in Pika. Run the existing signed hosted smoke and verify two simultaneous classes and a one-meeting room move in the target environment.

### Pika acceptance

- With two open P3 classes in Room 223, students enrolled in A, B, and both get exactly one accepted fact for each enrolled class, with one scan per student. Pika displays each class result and applies each class’s existing present/late rule. Repeating a scan creates no duplicate fact.
- The QR is unchanged after five minutes with the same accepting meetings. A start, stop, move, or new Toronto school day changes or clears the proof. A prior-day scan cannot mark today. An open prior-day room meeting does not block today’s.
- Move P5 to Room 220 while another meeting remains in Room 223. New scans in 220 can mark P5. A scan already captured in 223 can still mark the other eligible meeting. Undo restores P5 without restoring a stale scan. Saving 220 as the default makes the next meeting open there.
- A Pika class without a room assignment continues through the existing classroom QR. The Pika pilot uses global teacher accounts for room management and student accounts for room check-in. Room-assigned meetings only accept the room proof. An unauthorized teacher cannot change room assignment or display settings.
